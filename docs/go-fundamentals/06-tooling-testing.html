Tooling, Testing và Workflow Trong Go

Mục tiêu: Thành thạo Go toolchain, viết test chuyên nghiệp, debug và profile hiệu quả. So sánh trực tiếp với npm/Jest/ESLint để bạn map kiến thức nhanh.

1. Go Toolchain

1.1 go run, go build, go install

bash
# Chạy file trực tiếp (compile + run, không tạo binary)
go run main.go
go run . # Chạy package trong thư mục hiện tại

# Compile thành binary
go build                    # Tạo binary tên giống thư mục
go build -o myapp           # Đặt tên binary
go build -o ./bin/myapp     # Output vào thư mục khác

# Chạy binary đã compile
./myapp

# Install - compile và copy binary vào $GOPATH/bin
go install                  # Binary tên giống module
go install ./cmd/api        # Install specific package

So sánh với Node.js:

Go Node.js
go run main.go node main.js
go build -o myapp npm run build (tùy framework)
go install npm install -g .
Binary standalone Cần Node.js runtime

Điểm mạnh Go: Binary standalone, không cần runtime. Deploy chỉ cần copy 1 file.

1.2 go mod - Dependency Management

bash
# Khởi tạo module mới (tương đương npm init)
go mod init github.com/username/myapp

# Thêm dependency (tương đương npm install)
go get github.com/go-chi/chi/v5
go get github.com/go-chi/chi/v5@v5.0.10    # Specific version
go get github.com/go-chi/chi/v5@latest      # Latest version

# Cleanup unused dependencies (tương đương npm prune)
go mod tidy

# Download dependencies vào vendor/
go mod vendor

# Xem dependency graph
go mod graph

# Verify checksums
go mod verify

# Xem giải thích tại sao cần dependency
go mod why github.com/some/package

# Edit module path
go mod edit -module new/path

So sánh với npm:

Go npm
go.mod + go.sum package.json + package-lock.json
go mod init npm init
go get pkg npm install pkg
go mod tidy npm prune + npm install
go mod vendor npm ci (với lockfile)
go mod graph npm ls
go.sum (checksums) package-lock.json (integrity)

go.mod file:

go
module github.com/username/myapp

go 1.22

require (
    github.com/go-chi/chi/v5 v5.0.10
    github.com/golang-jwt/jwt/v5 v5.2.0
    github.com/lib/pq v1.10.9
)

require (
    // Indirect dependencies (của dependencies)
    golang.org/x/crypto v0.17.0 // indirect
)

go.sum file: - Chứa cryptographic hashes của dependencies - Tương tự package-lock.json nhưng chỉ chứa checksums - Commit vào git để đảm bảo reproducible builds

1.3 go fmt - Non-negotiable trong Go Culture

bash
# Format tất cả files trong package
go fmt ./...

# Format specific file
go fmt main.go

# Check formatting mà không sửa (dùng trong CI)
gofmt -l .                  # Liệt kê files cần format
gofmt -d .                  # Hiển thị diff

# go fmt = gofmt -l -w (tự động sửa)

Quan trọng: - Go community CỰC KỲ strict về formatting - Không có debates về tabs vs spaces, braces placement, etc. - go fmt là tool duy nhất - mọi người dùng cùng style - Code không format = code không review được

So sánh với JavaScript:

bash
# JavaScript - nhiều tools khác nhau
eslint --fix .
prettier --write .
standard --fix

# Go - chỉ 1 tool
go fmt ./...

1.4 go vet - Static Analysis

go
// go vet tìm các lỗi phổ biến mà compiler không bắt

// Ví dụ 1: Printf format mismatch
fmt.Printf("Hello %s", 123)  // ❌ vet warning: %s với int

// Ví dụ 2: Unreachable code
func example() {
    return
    fmt.Println("never")  // ❌ vet warning: unreachable
}

// Ví dụ 3: Struct tag errors
type User struct {
    Name string `json:"name`
    // ❌ vet warning: missing closing quote
}

// Ví dụ 4: Unused result của certain functions
fmt.Println("hello")  // Kết quả bị bỏ qua (ok)
strconv.Atoi("123")   // ❌ vet warning: result unused
bash
# Chạy vet
go vet ./...

# Vet là 1 phần của go test
go test ./...  # Tự động chạy vet trước khi test

1.6 Cross-Compilation

Go compile native code cho mọi platform. Không cần cross-compile tools:

bash
# Xem danh sách platforms hỗ trợ
go tool dist list

# Compile cho Linux từ macOS/Windows
GOOS=linux GOARCH=amd64 go build -o myapp-linux

# Compile cho Windows
GOOS=windows GOARCH=amd64 go build -o myapp.exe

# Compile cho macOS ARM (M1/M2)
GOOS=darwin GOARCH=arm64 go build -o myapp-mac-arm

# Compile cho macOS Intel
GOOS=darwin GOARCH=amd64 go build -o myapp-mac-intel

# Compile cho ARM (Raspberry Pi)
GOOS=linux GOARCH=arm GOARM=7 go build -o myapp-arm

# Compile cho Alpine Linux (dùng musl)
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o myapp-alpine

Dockerfile cho Go (multi-stage build):

dockerfile
# Build stage
FROM golang:1.22-alpine AS builder
WORKDIR /app
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -o myapp ./cmd/api

# Runtime stage
FROM alpine:latest
RUN apk --no-cache add ca-certificates
COPY --from=builder /app/myapp /usr/local/bin/
EXPOSE 8080
CMD ["myapp"]

1.8 ldflags - Version Injection

Inject version info vào binary tại build time:

go
// main.go
package main

import "fmt"

// Biến sẽ được set qua ldflags
var (
    version   = "dev"
    commit    = "unknown"
    buildTime = "unknown"
)

func main() {
    fmt.Printf("Version: %s\n", version)
    fmt.Printf("Commit: %s\n", commit)
    fmt.Printf("Built: %s\n", buildTime)
}
bash
# Build với version info
go build -ldflags "\
  -X main.version=1.0.0 \
  -X main.commit=$(git rev-parse --short HEAD) \
  -X main.buildTime=$(date -u +%Y-%m-%dT%H:%M:%SZ) \
" -o myapp .

# Chạy
./myapp
# Output:
# Version: 1.0.0
# Commit: abc1234
# Built: 2024-01-15T10:30:00Z

Makefile helper:

makefile
VERSION := $(shell git describe --tags --always)
COMMIT := $(shell git rev-parse --short HEAD)
BUILD_TIME := $(shell date -u +%Y-%m-%dT%H:%M:%SZ)

LDFLAGS := -ldflags "\
  -X main.version=$(VERSION) \
  -X main.commit=$(COMMIT) \
  -X main.buildTime=$(BUILD_TIME)"

build:
	go build $(LDFLAGS) -o bin/myapp ./cmd/api

build-all:
	GOOS=linux GOARCH=amd64 go build $(LDFLAGS) -o bin/myapp-linux ./cmd/api
	GOOS=darwin GOARCH=arm64 go build $(LDFLAGS) -o bin/myapp-mac ./cmd/api
	GOOS=windows GOARCH=amd64 go build $(LDFLAGS) -o bin/myapp.exe ./cmd/api

1.9 Quản lý Nhiều Phiên bản Go (nvm ↔ goenv / GOTOOLCHAIN)

Trong Node.js bạn quen với nvm install 20 && nvm use 20. Go không có nvm chính chủ, nhưng có 4 cách — trong đó từ Go 1.21+ cách chuẩn là GOTOOLCHAIN: lệnh go tự tải và tự switch đúng version theo go.mod, không cần cài tool gì thêm.

Cách 1: GOTOOLCHAIN — cơ chế chính chủ từ Go 1.21 (khuyến nghị)

Khai báo version ngay trong go.mod, giống engines trong package.json nhưng tự động:

go
// go.mod
module myapp

go 1.22.0          // version tối thiểu của project (như "engines": {"node": ">=20"})
toolchain go1.22.5 // toolchain cụ thể muốn dùng
bash
go env GOTOOLCHAIN    # mặc định: auto

# auto: project cần Go mới hơn -> lệnh go TỰ download & dùng, không cần làm gì
go version            # go version go1.22.5 ...

# Ép dùng đúng một version cho 1 lần chạy (như nvm exec)
GOTOOLCHAIN=go1.21.3 go build ./...

# Chỉ dùng toolchain đã cài, không bao giờ tự tải (hay dùng cho CI, offline)
GOTOOLCHAIN=local go test ./...

# Set vĩnh viễn (như nvm alias default)
go env -w GOTOOLCHAIN=auto
📦**Node.js → Go mapping
  • .nvmrc ↔ dòng go 1.22 trong go.mod (khi GOTOOLCHAIN=auto)
  • nvm use ↔ tự động khi cd vào project, không cần gõ lệnh nào
  • nvm exec 18 ... ↔ GOTOOLCHAIN=go1.21.3 go build ./...
  • nvm alias default ↔ go env -w GOTOOLCHAIN=auto

💡 Thực tế: chỉ cần cd vào project có go 1.23 trong go.mod là mọi lệnh go ... đã chạy bằng toolchain 1.23. Người Go lâu năm hầu như không cài thêm gì nữa.

Cách 2: goenv — giống nvm nhất (shim-based)

Đúng như bạn đoán, Go có goenv — viết theo mô-típ pyenv/nvm, quản lý version qua shims (~/.goenv/shims/go chặn lệnh go và route tới version đã chọn):

bash
# Cài goenv (Linux/WSL/macOS)
git clone https://github.com/goenv/goenv.git ~/.goenv
export GOENV_ROOT="$HOME/.goenv"
export PATH="$GOENV_ROOT/bin:$PATH"
eval "$(goenv init -)"    # thêm 3 dòng này vào .bashrc/.zshrc

# Lệnh 1-1 với nvm
goenv install --list      # nvm ls-remote
goenv install 1.22.1      # nvm install 20
goenv global 1.22.1       # nvm alias default 20
goenv local 1.21.5        # nvm use (ghi vào file .go-version của thư mục)
goenv versions            # nvm ls

Cách 3: g — nhẹ hơn goenv, phổ biến trong cộng đồng Go

g (voidint/g) dùng symlink $GOROOT thay vì shims nên chuyển version nhanh hơn:

bash
g ls-remote        # nvm ls-remote
g install 1.22.1   # nvm install
g use 1.22.1       # nvm use
g ls               # nvm ls

Cách 4: asdf / mise — nếu bạn đã dùng chúng cho Node

bash
# mise (kế thừa asdf, quản lý nhiều runtime: node + go + python)
mise use --global node@20
mise use --global go@1.22.1

# asdf
asdf plugin add golang https://github.com/asdf-community/asdf-golang.git
asdf install golang 1.22.1
asdf global golang 1.22.1

So sánh nhanh — chọn cái nào?

Cách Cơ chế Giống nvm nhất ở điểm Khi nào dùng
GOTOOLCHAIN (Go 1.21+) go tự tải theo go.mod nvm use tự động theo project ✅ Mặc định — không cài gì thêm

Ngoài ra Go còn có cách chính chủ để cài song song nhiều version (wrapper binary, không phải switch):

bash

✅ Khuyến nghị cho dev Node chuyển sang Go: đừng vội cài goenv. Để mặc định GOTOOLCHAIN=auto + ghi go 1.x trong go.mod — mỗi project tự dùng đúng version, teammate clone về là có ngay môi trường chuẩn. Chỉ cài goenv/g/mise khi bạn cần chạy nhiều version ngoài project (build thử bản cũ, debug toolchain...).

2. Testing - Exhaustive

2.1 Testing Package Deep Dive

Cấu trúc file test: - File test: user_test.go (cùng package với user.go) - Function test: func TestXxx(t *testing.T) (bắt đầu bằng Test) - Package: _test suffix (black-box) hoặc cùng package (white-box)

go
// user.go
package user

type User struct {
    Name  string
    Email string
}

func ValidateEmail(email string) bool {
    return strings.Contains(email, "@")
}
go
// user_test.go - White-box test (cùng package)
package user

import "testing"

func TestValidateEmail(t *testing.T) {
    if !ValidateEmail("test@example.com") {
        t.Error("expected valid email")
    }
    if ValidateEmail("invalid") {
        t.Error("expected invalid email")
    }
}
go
// user_test.go - Black-box test (khác package)
package user_test

import (
    "testing"
    "myapp/user"
)

func TestValidateEmail(t *testing.T) {
    if !user.ValidateEmail("test@example.com") {
        t.Error("expected valid email")
    }
}

Testing.T methods:

go
func TestExample(t *testing.T) {
    // Log (chỉ hiện khi test fail hoặc -v)
    t.Log("this is a log message")

    // Fail - đánh dấu fail nhưng tiếp tục chạy
    t.Fail()

    // FailNow - đánh dấu fail và dừng test ngay
    t.FailNow()

    // Error - Log + Fail
    t.Error("something went wrong")

    // Fatal - Log + FailNow
    t.Fatal("cannot continue")

    // Skip - bỏ qua test
    if runtime.GOOS == "windows" {
        t.Skip("skipping on windows")
    }

    // Helper - đánh dấu là helper function
    t.Helper()

    // Cleanup - chạy sau khi test xong
    t.Cleanup(func() {
        os.Remove("temp-file")
    })

    // Parallel - chạy song song với tests khác
    t.Parallel()
}

2.2 Table-Driven Tests

Đây là pattern idiomatic nhất trong Go:

go
func TestAdd(t *testing.T) {
    tests := []struct {
        name     string
        a, b     int
        expected int
   }{
        {"positive numbers", 2, 3, 5},
        {"negative numbers", -2, -3, -5},
        {"zero", 0, 0, 0},
        {"mixed signs", -2, 3, 1},
        {"large numbers", 1000000, 2000000, 3000000},
    }

    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            got := Add(tt.a, tt.b)
            if got != tt.expected {
                t.Errorf("Add(%d, %d) = %d, want %d", tt.a, tt.b, got, tt.expected)
            }
        })
    }
}

Table-driven test cho HTTP handler:

go
func TestCreateUser(t *testing.T) {
    tests := []struct {
        name       string
        body       string
        wantStatus int
        wantErr    string
    }{
        {
            name:       "valid input",
            body:       `{"name":"John","email":"john@example.com"}`,
            wantStatus: http.StatusCreated,
        },
        {
            name:       "missing name",
            body:       `{"email":"john@example.com"}`,
            wantStatus: http.StatusBadRequest,
            wantErr:    "name is required",
        },
        {
            name:       "invalid email",
            body:       `{"name":"John","email":"invalid"}`,
            wantStatus: http.StatusBadRequest,
            wantErr:    "invalid email",
        },
        {
            name:       "invalid JSON",
            body:       `{invalid`,
            wantStatus: http.StatusBadRequest,
            wantErr:    "invalid JSON",
        },
        {
            name:       "empty body",
            body:       "",
            wantStatus: http.StatusBadRequest,
        },
    }

    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            // Setup
            repo := repository.NewInMemoryUserRepository()
            svc := service.NewUserService(repo)
            handler := handler.NewUserHandler(svc)

            // Create request
            req := httptest.NewRequest(http.MethodPost, "/api/users", strings.NewReader(tt.body))
            req.Header.Set("Content-Type", "application/json")
            rr := httptest.NewRecorder()

            // Execute
            handler.CreateUser(rr, req)

            // Assert
            if rr.Code != tt.wantStatus {
                t.Errorf("status = %d, want %d", rr.Code, tt.wantStatus)
            }

            if tt.wantErr != "" {
                var resp map[string]string
                json.NewDecoder(rr.Body).Decode(&resp)
                if resp["error"] != tt.wantErr {
                    t.Errorf("error = %q, want %q", resp["error"], tt.wantErr)
                }
            }
        })
    }
}

2.3 Subtests

go
func TestUserService(t *testing.T) {
    repo := repository.NewInMemoryUserRepository()
    svc := service.NewUserService(repo)

    // Tạo user trước
    user, err := svc.CreateUser(model.CreateUserRequest{
        Name:  "John",
        Email: "john@example.com",
    })
    if err != nil {
        t.Fatalf("failed to create user: %v", err)
    }

    // Subtests share state
    t.Run("GetUser", func(t *testing.T) {
        got, err := svc.GetUser(user.ID)
        if err != nil {
            t.Fatalf("GetUser() error = %v", err)
        }
        if got.Name != "John" {
            t.Errorf("Name = %q, want %q", got.Name, "John")
        }
    })

    t.Run("UpdateUser", func(t *testing.T) {
        newName := "Jane"
        got, err := svc.UpdateUser(user.ID, model.UpdateUserRequest{
            Name: &newName,
        })
        if err != nil {
            t.Fatalf("UpdateUser() error = %v", err)
        }
        if got.Name != "Jane" {
            t.Errorf("Name = %q, want %q", got.Name, "Jane")
        }
    })

    t.Run("DeleteUser", func(t *testing.T) {
        err := svc.DeleteUser(user.ID)
        if err != nil {
            t.Fatalf("DeleteUser() error = %v", err)
        }

        // Verify deleted
        _, err = svc.GetUser(user.ID)
        if err == nil {
            t.Error("expected error after delete")
        }
    })
}

2.4 Test Fixtures

go
// testdata/ directory - Go convention
// testdata/ được tự động ignore bởi go tools

func TestParseConfig(t *testing.T) {
    // Đọc fixture file
    data, err := os.ReadFile("testdata/config.json")
    if err != nil {
        t.Fatalf("failed to read fixture: %v", err)
    }

    cfg, err := ParseConfig(data)
    if err != nil {
        t.Fatalf("ParseConfig() error = %v", err)
    }

    if cfg.Port != 8080 {
        t.Errorf("Port = %d, want 8080", cfg.Port)
    }
}

// Tạo fixture helper
func writeFixture(t *testing.T, name string, data []byte) {
    t.Helper()
    path := filepath.Join("testdata", name)
    if err := os.WriteFile(path, data, 0644); err != nil {
        t.Fatalf("failed to write fixture: %v", err)
    }
}

Test fixtures với golden files:

go
func TestRenderTemplate(t *testing.T) {
    got := RenderTemplate(data)

    golden := filepath.Join("testdata", t.Name()+".golden")

    if *update {
        // Cập nhật golden file: go test -update
        os.WriteFile(golden, []byte(got), 0644)
        return
    }

    want, err := os.ReadFile(golden)
    if err != nil {

2.9 Fuzzing (Go 1.18+)

Fuzzing tự động tạo test inputs để tìm bugs:

go
// Fuzz function bắt đầu bằng Fuzz
func FuzzReverse(f *testing.F) {
    // Seed corpus - inputs ban đầu
    f.Add("hello")
    f.Add("world")
    f.Add("")
    f.Add("a")

    // Fuzz function
    f.Fuzz(func(t *testing.T, input string) {
        // Reverse twice should return original
        reversed := Reverse(input)
        doubleReversed := Reverse(reversed)

        if input != doubleReversed {
            t.Errorf("Reverse(Reverse(%q)) = %q, want %q", input, doubleReversed, input)
        }
    })
}

func FuzzParseUser(f *testing.F) {
    f.Add([]byte(`{"name":"John","age":30}`))
    f.Add([]byte(`{}`))

    f.Fuzz(func(t *testing.T, data []byte) {
        user, err := ParseUser(data)
        if err != nil {
            return // Invalid input is ok
        }

        // User should be valid after parsing
        if user.Name == "" && user.Age != 0 {
            t.Errorf("inconsistent user: %+v", user)
        }
    })
}

4.5 Race Detector

Go có built-in race detector để tìm data races:

go
// Code có race condition
func main() {
    counter := 0

    var wg sync.WaitGroup
    for i := 0; i < 1000; i++ {
        wg.Add(1)
        go func() {
            defer wg.Done()
            counter++ // ❌ Race condition!
        }()
    }
    wg.Wait()
    fmt.Println(counter)
}
bash
# Chạy với race detector
go run -race main.go
go test -race ./...
go build -race -o myapp && ./myapp

Output khi detect race:

WARNING: DATA RACE
Write at 0x00c0000b4010 by goroutine 8:
  main.main.func1()
      /path/to/main.go:12 +0x4e

Previous write at 0x00c0000b4010 by goroutine 7:
  main.main.func1()
      /path/to/main.go:12 +0x4e

Fix race condition:

go
func main() {
    var counter int64

    var wg sync.WaitGroup
    for i := 0; i < 1000; i++ {
        wg.Add(1)
        go func() {
            defer wg.Done()
            atomic.AddInt64(&counter, 1) // ✅ Thread-safe
        }()
    }
    wg.Wait()
    fmt.Println(counter)
}

5.4 CI/CD Patterns

GitHub Actions:

yaml
# .github/workflows/ci.yml
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-go@v5
        with:
          go-version: '1.22'

      - name: Download dependencies
        run: go mod download

      - name: Format check
        run: |
          if [ -n "$(gofmt -l .)" ]; then
            echo "Files not formatted:"
            gofmt -l .
            exit 1
          fi

      - name: Vet
        run: go vet ./...

      - name: Lint
        uses: golangci/golangci-lint-action@v3
        with:
          version: latest

      - name: Test
        run: go test -race -coverprofile=coverage.out ./...

      - name: Upload coverage
        uses: codecov/codecov-action@v3
        with:
          file: coverage.out

  build:
    needs: test
    runs-on: ubuntu-latest
    strategy:
      matrix:
        goos: [linux, darwin, windows]
        goarch: [amd64, arm64]
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-go@v5
        with:
          go-version: '1.22'

      - name: Build
        env:
          GOOS: ${{ matrix.goos }}
          GOARCH: ${{ matrix.goarch }}
        run: |
          go build -ldflags="-s -w" -o myapp-${{ matrix.goos }}-${{ matrix.goarch }} ./cmd/api

      - name: Upload artifact
        uses: actions/upload-artifact@v4
        with:
          name: myapp-${{ matrix.goos }}-${{ matrix.goarch }}
          path: myapp-*

6. Dependency Management

6.1 go get vs go install

bash
# go get - thêm dependency vào go.mod
go get github.com/go-chi/chi/v5

go get -u=patch ./...              # Update patch versions only

6.2 Module Versioning

Go modules dùng semantic versioning:

go
// go.mod
require (
    github.com/foo/bar v1.2.3        // Release version
    github.com/foo/bar v1.2.4-0.20230101120000-abcdef123456  // Pseudo-version (pre-release)
    github.com/foo/bar v0.0.0-20230101120000-abcdef123456     // No release yet
)
bash
# Xem versions available
go list -m -versions github.com/go-chi/chi/v5

# Xem version hiện tại
go list -m github.com/go-chi/chi/v5

# Pin version
go get github.com/go-chi/chi/v5@v5.0.10

# Upgrade minor
go get github.com/go-chi/chi/v5@v5.1.0

# Upgrade major (thay đổi import path)
go get github.com/foo/bar/v2

Major version convention:

go
// v0.x.x và v1.x.x - cùng import path
import "github.com/foo/bar"

// v2.x.x+ - phải thêm /v2 vào import path
import "github.com/foo/bar/v2"

// go.mod
module github.com/foo/bar/v2

6.3 Replace Directives

go
// go.mod
module myapp

require (
    github.com/some/dependency v1.0.0
)

// Replace với local path (development)
replace github.com/some/dependency => ../dependency

// Replace với fork
replace github.com/some/dependency => github.com/myfork/dependency v1.0.1

// Replace với specific version
replace github.com/some/dependency v1.0.0 => github.com/some/dependency v1.0.1

Khi nào dùng replace: - Local development (chưa publish) - Fork cần fix bug - Test với local changes

Lưu ý: replace trong go.mod không ảnh hưởng khi package được import bởi project khác.
